통합회원 어드민 개편

2026.04 ~ 진행 중

여러 기능이 섞여 있던 관리자 사이트에서 통합회원 관리를 독립된 시스템으로 분리

  • 프론트엔드, API 연결, 권한 DB 설계
  • Next.js
  • Keycloak (OIDC·OAuth2 SSO)
  • DB 설계
  • 암복호화
  • Audit Log

상황

기존 관리자 사이트에는 여러 도메인의 기능이 섞여 있었고, 민감한 통합회원 데이터도 그 안에 있었습니다. 신규 조직(그룹)이 들어올 때마다 권한을 수동으로 DB에 등록해야 해서 누락과 매칭 오류가 반복됐습니다.

한 일

  • Keycloak(회원정보·그룹)과 내부 DB(메뉴별 권한)의 역할을 분리하고, 로그인 시점에 자동으로 Upsert해 권한이 매칭되도록 구조를 새로 만듦
  • 버튼·모달·폼 등 반복되는 UI를 공통 컴포넌트로 분리해 여러 관리자 화면에서 재사용
  • 요청이 올 때마다 개발자가 사이트별 페이지로 만들어 관리하던 약관을 사이트·문서유형·버전 단위로 데이터화하고, 관리자가 에디터로 직접 등록·수정하는 구조로 설계
  • 관리자의 모든 활동을 감사 로그로 남기고, 한 번에 전체를 불러오던 로그 목록을 페이지네이션으로 전환
  • 인증 서버(Keycloak)에 설정된 세션 만료 정책을 서버 미들웨어와 클라이언트 타이머 양쪽에 똑같이 반영해 자동 로그아웃 구현
  • 소셜·이메일·구 아이디로 흩어진 회원 데이터를 3가지 유형으로 나눠 통합 조회 가능하게 재구축

결과

수동 권한 등록이 사라졌고, 약관은 여러 사이트에 흩어진 페이지 대신 한 곳에서 관리하게 됐습니다.

수입차 브랜드 A 고객사 사이트 구축 및 운영

2025.02 ~ 진행 중

관리자 시스템을 제안하고 DB 설계부터 화면, 서버까지 직접 구축

  • 기획부터 풀스택 개발까지 단독
  • React
  • Node.js/Express
  • JWT
  • MariaDB

상황

고객사의 요청으로 기획 단계부터 개발까지 진행한 프로젝트입니다. 관리자 시스템의 필요성을 판단해 도입을 제안했고, 초기 규모가 크지 않아 백엔드 인력 없이 직접 진행했습니다.

한 일

  • 계정 테이블에 권한 레벨을 두고, 레벨 1은 글 작성만, 레벨 2는 전체 권한으로 구분
  • 로그인할 때 발급하는 JWT에 레벨을 담고, 수정·삭제·게시 API에서 서버가 레벨을 직접 확인해 권한이 없으면 거부
  • 화면에서 버튼을 숨기는 것만으로는 API를 직접 호출하면 우회되기 때문에, 최종 판단은 서버에 둠
  • 로그인 실패 시 계정 잠금, 비밀번호 유효기간, 활동 로그 등 계정 보안 정책 구현
  • 토큰은 HttpOnly 쿠키로 전달하고, 홈페이지 전체 구조부터 React 화면과 Node.js/Express 서버까지 전 구간 개발
  • 구축(2025.02 ~ 2025.07) 이후 콘텐츠 교체, 펌웨어 버전 업데이트 등 운영·유지보수를 지속 담당

결과

백엔드 인력 없이도 역할별로 권한이 나뉜 관리자 시스템을 갖춰, 고객사가 게시물을 직접 관리할 수 있게 됐습니다.

전사 웹사이트 운영 및 유지보수

2020.01 ~ 진행 중

브랜드 사이트, 쇼핑몰, 글로벌 채널의 고객 화면을 동시에 운영

  • 운영·유지보수 담당
  • 쇼핑몰
  • 브랜드 사이트
  • 글로벌 다국어
  • 약관 페이지

상황

세 채널을 동시에 운영하다 보니 채널마다 배포 일정이 달랐고, 다국어 페이지를 늘릴 때마다 같은 수정을 언어별로 반복해야 했습니다. 고객이 결과를 바로 확인하는 회원 화면이라 작은 오류도 곧바로 혼란으로 이어졌습니다.

한 일

  • 채널별로 흩어진 배포 일정을 통합 작업 기준(Standard)으로 정리해 표준화
  • 글로벌 홈페이지의 다국어 페이지에서 반복 요소를 컴포넌트 템플릿으로 만들어 수정 범위를 최소화
  • 마이페이지(회원정보·배송지), 주문/배송 조회, 포인트·쿠폰, 회원 등급 표시를 유지보수하며 이슈마다 원인부터 파악해 개선
  • 쇼핑몰 화면에 로딩 UI를 적용해 데이터를 불러오는 동안 진행 상태를 보여줌
  • 브랜드·쇼핑몰·통합회원별 이용약관과 통합약관 페이지를 요청에 따라 제작·관리

결과

언어가 늘어나도 반복 요소는 템플릿 한 곳만 고치면 되도록 바뀌었고, 세 채널의 배포가 하나의 기준 아래에서 진행되게 됐습니다.

통합회원 가입 폼 고도화

2025.11 ~ 2026.02

조건에 따라 달라지는 가입 흐름과 검증 로직을 다시 설계

  • 프론트엔드 개발
  • Next.js
  • 비동기 처리
  • 폼 아키텍처

상황

가입 경로(소셜/일반)와 약관 노출 조건에 따라 폼 구성이 달라져야 했고, 비동기 validation 타이밍 때문에 에러 표시가 남는 문제가 있었습니다. 제조사, 차종, 차급으로 이어지는 차량 정보 선택에서는 데이터 초기화 오류가 발생했습니다.

한 일

  • 가입 경로와 약관 노출 조건에 따라 폼이 바뀌는 분기 처리 구조를 설계하고, 약관 동의 항목이 조건에 따라 활성·비활성되도록 재설계
  • 비동기 validation 타이밍 이슈로 생기던 에러 잔상 문제를 해결
  • Select 필드의 공통 핸들러를 추상화해 중복 코드 제거
  • 차량 정보 선택의 조건식을 재설계해 데이터 초기화 오류를 개선하고, 마이페이지에서 변경한 값이 올바르게 저장되는지까지 검증
  • 클라이언트와 서버 사이의 데이터 형식(Boolean ↔ Y/N) 매핑 처리

결과

가입 경로가 달라도 하나의 폼 구조 안에서 분기되고, 차량 정보는 가입부터 마이페이지 수정까지 같은 값으로 유지됩니다.

수입차 브랜드 B 고객사 사이트 개편 및 운영

다국어 텍스트가 컴포넌트 안에 직접 적혀 있어서, 언어를 하나 추가하려면 여러 컴포넌트의 코드를 고쳐야 했습니다. 배포도 수동이라 사람의 실수가 끼어들 여지가 있었습니다.

한 일

  • 컴포넌트에 하드코딩된 다국어 텍스트를 언어별 JSON 리소스로 분리
  • GitHub Actions와 AWS CodeDeploy로 빌드부터 배포까지 자동화
  • 반응형 인터페이스로 다양한 디바이스 환경 지원
  • 개편(2024.05 ~ 2024.12) 이후 콘텐츠 교체, 펌웨어 버전 업데이트 등 운영·유지보수를 지속 담당
  • 고객사 요청으로 관리자 페이지 신규 도입을 설계 단계에서 진행 중

결과

언어를 추가할 때 코드 수정 없이 JSON 파일만 추가하면 되는 구조가 됐고, 수동 배포로 인한 실수가 사라져 배포가 늘 같은 방식으로 진행됩니다.
